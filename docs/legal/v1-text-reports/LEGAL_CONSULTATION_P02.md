# 法的確認の依頼資料：P02-2・P02-3（2026-11-28、未回答）

この資料は専門家への相談用にまとめたもので、法的な結論や承認ではない。**G23はOPEN。**
ここに書いた事実は、リポジトリのコードと既存の文書で確認できる範囲に限る。本番のデータ件数や個別の申請内容は含まない。

## 1. サービスと申請機能の概要

- MannerPath は、許可された喫煙場所・灰皿を探す iPhone / Apple Watch アプリ。
- v1.0 では、未掲載の場所をテキストで申請できる（写真は v1.1 以降）。**アカウントはない。**
- 送信は端末認証（App Attest）付き。申請者は端末ごとの鍵で区別され、氏名・メールアドレスは受け取らない。
- 申請は運営者が審査し、独立した根拠がそろった場合だけ地図に反映する。
- 現在、本番では申請の受付を開始していない。

## 2. 保持するデータ

| データ | 内容 | 扱い |
| --- | --- | --- |
| 申請の個人に関わる項目 | 本文、指定した位置、確認日、申請者との関連付け（`submitter_hash`）、自由記述の施設名・営業時間 | 受信から90日を基準に最小化（NULL化）する設計。自動処理はまだどの環境でも動いていない |
| 申請の残り | 受付ID、分類、同意した規約版、最小化した日時 | 残る。削除機能はない |
| 二重受付を防ぐ記録 | 同じ下書きの再送を拒否するための記録 | 90日の最小化と同時に退役する。削除機能はない |
| 端末認証の鍵・失効記録 | 不正送信と失効の迂回を防ぐ | 失効はできる（消去ではない） |
| 審査・監査の記録 | ID・状態・理由のみ。本文は持たない | 残る |
| 問い合わせ（support メール） | 相談内容 | 案件ごとに手作業で処理 |
| バックアップ・ログ | 提供者側の復元履歴・ログ | 提供者の設定に従う。一部未確認 |

詳細：[P01_P02_DECISIONS.md §1](P01_P02_DECISIONS.md#1-保持するデータごとの理由見直し時期削除条件)

## 3. 現在できること・できないこと

- **できる：** 申請を審査の対象から外す、公開に使わない状態にする、公開済みの情報を事実の再確認で非公開にする、90日での最小化。
- **できない：**
  - 申請者本人であることの確認（アカウントがなく、受付IDを知っていることは本人の証明にならない）
  - 90日より前の最小化
  - 行の完全な削除

## 4. 運営者が採用したい対応（条件付き、法的確認待ち）

- **P02-2 本人との関係を確認できない請求：** 開示・削除は行わず、90日での最小化を案内する。身分証は集めない。第三者の個人情報などの問題は、請求者の確認なしに内容で対応する。回答文案は [P01_P02_DECISIONS.md §5](P01_P02_DECISIONS.md#5-回答テンプレート実施した事実に合わせて担当者が選ぶ) のテンプレートB。
- **P02-3 第三者の個人情報が混入した申請：** まず利用を止め、運営者が内容を確認したうえで、その1件だけを90日より前に最小化する。この機能は未実装で、実装案（本体約30行・記録用の表1つ）は [P02_3_IMPLEMENTATION_PLAN.md](P02_3_IMPLEMENTATION_PLAN.md)。実装までの間はテンプレートC（利用は止めたが期限前の消去は準備中）を使う。

## 5. 確認したいこと（6問）

1. P02-2：アカウントがないため本人との関係を安全に確認できない。これを理由に開示・削除を断り、90日後の最小化を案内する対応でよいか。回答に何を書けばよいか。
2. P02-2：report ID や申請内容を知っていることを本人確認とみなさず、身分証も集めない方針でよいか。
3. P02-3：第三者の個人情報が含まれる申請を、請求者の確認なしに、運営者が内容に基づいて期限前に最小化する対応は適切か。
4. P02-3：実装が完了するまでの間、「利用を止め、準備ができたら消去する」という対応で足りるか。
5. 共通：最小化した後も、受付ID・分類・審査記録・バックアップが残ることは許されるか。規約での説明は必要か。
6. 共通：回答期限と、記録として残すべき内容は何か。
