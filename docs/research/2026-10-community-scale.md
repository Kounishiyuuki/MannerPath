## Highest rollout capacity risks

1. **D1 SQL import ceiling:** largest 50k tile INSERT is 1,552,013bytes versus the currently documented 100 KB statement limit (medium 330,254bytes). Local import success is not a shippable D1 bundle.
2. **Dense tile/device rendering:** Umeda has 2,223spots, 1,551,737raw bytes, 33,043gzip bytes; existing 250/16KiB reevaluation limits are exceeded. Apple annotation rendering remains unclustered and requires device profiling.
3. **Offline memory:** peak RSS in the full large diagnostic includes both source/target SQLite databases and generation/verification/re-export, not one Worker request. Read per-phase memory in explicit benchmark JSON; the table above is the measured host high-water. 300.86 MB SQL is still held as a complete string.
4. **Atomic publication batch:** large publishes 8.24s locally with 51,419maximum batch statements. No unsafe partial canonical updates were introduced; real D1 batch duration/memory remains unverified.
5. **Bootstrap/verification growth:** large atomic bootstrap 20.96s after indexes; promotion generation 7.28s plus verification 0.69s. More rows approach infrastructure duration/memory boundaries, so rerun before the next capacity step.
